# Troubleshooting

Use this section before escalating a problem. The goal is to establish whether the issue is access, configuration, availability, order submission, payment, fulfilment or notification.

## First-response sequence

1. Stop repeated submissions or payments.
2. Record the product, vendor, site and channel.
3. Capture the order number or reference, if one exists.
4. Record the exact time and visible status.
5. Check connectivity and refresh once.
6. Confirm the signed-in role and active site.
7. Follow the product-specific guide.
8. If unresolved, use the [support escalation checklist](escalation.md).

## Safety rules

- Do not submit an order again until you know whether the first submission succeeded.
- Do not repeat a payment because a confirmation screen is slow.
- Do not change capacity, stock or site access merely to hide a symptom.
- Never include passwords, full card details or private customer data in screenshots.
